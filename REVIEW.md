# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` (lines 33-37) | Direct datetime replacement on UTC instant ignores IST timezone; compares UTC time directly against IST shift start. | Punch-in at 09:30 IST (04:00 UTC) gets compared to 09:30 UTC, showing employee as 330 minutes early or late. | Converted epoch milliseconds to IST timezone (`Asia/Kolkata` / `+05:30`) before extracting date and calculating time differences. |
| 2 | `compute_late_minutes` (line 37) | Grace period threshold defect: `minutes if minutes > 10 else 0`. At 09:40:01 (10 min 1 sec after 09:30), elapsed minutes floor is 10; `10 > 10` evaluates to False, incorrectly returning 0. | Input `09:40:01` returns `0` instead of `10` as mandated by Rule R2. | Checked strict second threshold `diff_seconds > 600` (strictly more than 10:00), then floored whole minutes `diff_seconds // 60`. |
| 3 | `compute_late_minutes` (lines 33-37) | Instants are not truncated to whole seconds before calculation, violating Rule R1. | Punch-in at `09:40:00.900` would calculate elapsed seconds with milliseconds. | Truncated epoch milliseconds to whole seconds `(ms // 1000) * 1000` prior to any calculation. |
| 4 | `compute_late_minutes` (lines 33-37) | Overnight shifts (`shift_end <= shift_start`) are not handled; punch-in after midnight compares against same calendar day shift start. | Punch-in at 00:15 for a 22:00-06:00 shift calculates a negative elapsed time or massive discrepancy. | Anchor shift start to the attendance date derived via overnight shift rules (R1). |
| 5 | `compute_work_hours` (line 41) | Uses Python built-in `round()`, which applies banker's rounding (round half to even) instead of half-up rounding (R4). | Duration of 2.675 hours produces 2.67 instead of 2.68. | Used `Decimal(sec) / Decimal(3600)` with `quantize(Decimal("0.01"), rounding=ROUND_HALF_UP)`. |
| 6 | `compute_overtime` (line 47) | Returns `max(0, minutes)` without enforcing the 30-minute minimum threshold (R3). | Punching out 15 minutes after shift end gives 15 minutes overtime instead of 0. | Added check: `if diff_seconds >= 1800: return diff_seconds // 60 else: return 0`. |
| 7 | `compute_overtime` (line 46) | For overnight shifts, shift end falls on the next calendar day, but starter sets `end` on `date_str` (the start day). | Overnight shift (22:00 - 06:00) punched out at 06:40 compares against 06:00 of the previous day (24+ hours overtime). | If `shift_end <= shift_start`, advance the target date by +1 day for `shift_end`. |
| 8 | `GET /health` (lines 72-74) | Unconditionally returns 200 without checking if MongoDB is responsive. | Stop or disconnect MongoDB; endpoint still returns `200 OK` instead of required `503`. | Executed `client.admin.command("ping")` inside a try/except block; raises HTTP 503 on failure. |

| 10 | `POST /employees` (lines 53-60) | Missing input validations: `shift_start` can equal `shift_end`, invalid `emp_code` format accepted, invalid email accepted. | Creating employee with `shift_start="09:30"` and `shift_end="09:30"` succeeds with 201 instead of 422. | Added Pydantic field validators for regex patterns, lengths, and verified `shift_start != shift_end`. |

| 12 | `GET /employees` (line 93) | Off-by-one pagination bug: `skip = page * page_size` skips the first page entirely when `page = 1`. | Querying `/employees?page=1&page_size=20` returns items 21-40 rather than 1-20. | Corrected skip formula to `skip = (page - 1) * page_size`. |

## Items Examined and Decided Were NOT Defects

1. **`load_dotenv()` at top level**:
   - Calling `load_dotenv()` is standard for local testing. Environment variables passed in the environment still take precedence over `.env` files in `python-dotenv`, satisfying the environment contract.
2. **Reading `MONGO_URI` and `MONGO_DB` from `os.getenv` with sensible fallbacks**:
   - Having default fallbacks (`mongodb://localhost:27017` and `attendance_db`) is convenient for zero-config local development, while allowing grader-provided environment variables to override them seamlessly.
3. **Pydantic model usage for request payloads**:
   - The basic structure of defining input schemas using Pydantic is appropriate and idiomatic in FastAPI; only the validation rules, constraints, and field types needed enhancement.
